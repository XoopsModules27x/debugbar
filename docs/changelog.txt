<h5>1.4.1 - [2026-08-08]</h5>
<hr>

<strong>Changed</strong>
- The Diagnostics row for the error screen now reports who actually owns PHP's handlers rather than whether Tracy is installed. It read XOOPS_TRACY_STATUS, so a site running xWhoops saw "Not installed" while Whoops held the handlers. XOOPS 2.7.3 publishes XOOPS_ERROR_SCREEN_OWNER / _SOURCE / _STATUS / _MESSAGE for any provider, and the row reads those. The Tracy library keeps a plain package row alongside Whoops.

<strong>Fixed</strong>
- The Tracy toolbar toggle no longer erases the rest of xoops_data/data/debug-runtime.json. It wrote the file wholesale, which was harmless while tracy_enabled was the only key in it; since 2.7.3 the core keeps the recorded error-screen owner there, so one press of the button dropped that record. The toggle now writes through the core's xoops_writeDebugRuntimeOverride(), which merges rather than replaces.

<h5>1.4.0 - [2026-08-04]</h5>
<hr>

Reconciles this module with the parallel copy maintained on the XMF 2.0 line, harvesting what that line did better and fixing three features that had shipped without working.

<h5>Added</h5>

- Added call-site attribution to query findings. The N+1 and duplicate detection could report that sixty-two identical statements ran but not which code ran them. A trimmed backtrace is now captured with each query, dropping the database drivers, the logger, this module and the generic persistence layer as never being the interesting caller, and the analyzer groups the surviving frames per statement and per shape, ranked by frequency. On the first real page it saw this named a genuine N+1 in Publisher: sixty-two executions from ItemHandler.php:255 and sixty-one from class/model/stats.php:52. Capture happens inside the existing query-log cap, so the cost stays bounded.
- Added a Boot / SQL / App time split, naming whichever segment dominated the request — the granularity that decides what to do next, since a request dominated by App time will not be improved by query tuning. It appears on the Performance panel, and the Server-Timing header now reports boot, db with its query count, app and total instead of one lumped figure.
- Added the per-request block cache split. A front page rendering nineteen uncached blocks pays nineteen block renders, each with its own queries, on every view. blocks_cached and blocks_uncached are stored per profile and averaged into the per-module Analytics table. Existing installations gain the columns through an idempotent migration.
- Added real-user monitoring: assets/xoops-debugbar-rum.js collects field web vitals (LCP, INP, CLS) in the browser and posts them to a new beacon.php endpoint via navigator.sendBeacon(), which attaches them to the matching stored profile. The Analytics page gained a Field web-vitals table of per-URL averages. The endpoint is POST-only and gated on module admin, XOOPS debug mode, a DEBUGBAR_RUM token, and a shape-validated request id.
- Added an Xdebug profile viewer. CachegrindParser reads cachegrind.out.* output (plain or gzip-compressed) into an immutable CachegrindResult, and the Analytics page lists profiles with creator, command, total cost, and a top-functions breakdown by inclusive/self cost. Profiles can be deleted individually or purged, both behind CSRF tokens.
- Added AssetScanner, which scans rendered HTML for script and stylesheet tags, sums local asset sizes, and flags a duplicated JavaScript runtime (two copies of jQuery, Alpine, htmx, and similar) on one page.
- Added AnalyticsBuilder, which aggregates stored profiles, flight-recorder dumps, and OPcache health into plain arrays, leaving the admin page responsible only for rendering and escaping.
- Added AccessPolicy, centralising the "may this admin page run" decision for pages that expose profiling data.
- Added RequestShape, sharing fragment/AJAX detection and URL normalisation between the logger and the profiler.
- Added QueryFingerprinter, normalising statements so structurally identical queries differing only in literal values can be grouped for N+1 and repeat analysis.
- Added CachegrindCatalog::delete(). The Analytics page already offered a per-profile Delete button that called this method, so pressing it raised a fatal "call to undefined method" error.
- Added SQL syntax highlighting to the Queries panel. The highlighter had shipped in assets/vendor/highlightjs since the module began without anything ever loading it, so every statement rendered as flat text. It publishes under its own class prefix and cannot collide with a copy the page loads. Rows are highlighted in place rather than only once expanded, and the theme follows the toolbar's light and dark modes. Both the highlighted and the fallback path escape.
- Implemented the collect_events preference, which had shipped since the module began with nothing behind it. XoopsPreload::triggerEvent() asks isset($this-&gt;_events[$name]) before dispatching, so standing an ArrayObject in for the event table makes every dispatch observable, including the events nothing listens to, which on a stock site is most of them. From outside, "my hook never ran" and "the event never fired" look identical, and watching the listeners instead can only ever see the former. Listeners are handed back wrapped in a timing proxy, so each is timed while still running normally, and one that throws still throws.
- Implemented the collect_templates preference, also previously inert. Every template XOOPS renders goes through the db: Smarty resource, and a registered resource takes precedence over the one Smarty autoloads, so a subclass registered from core.class.template.new records each render with the source that served it (theme override, module file or database) plus its size, render count and fetch time. The origin is established by matching the modification time and size of the candidate files against the bytes core actually returned, rather than repeating core's private resolution logic, so it costs no extra queries. Two indistinguishable candidates are reported as ambiguous rather than guessed between.
- Added three budget checks the profiler already had the data for but never reported: failed queries, a fragment request that rendered the full theme, and more than one copy of the same JavaScript runtime on a page. The last is what the asset scanner detects, so its findings now reach the stored profile, the Analytics violations feed and the flight recorder instead of only the Performance panel.

<h5>Fixed</h5>

- Connected the editor source links, which had never worked. The toolbar has rendered clickable file:line links for four kinds of row since it was written, but nothing gave them a file: the logger called collectFileTrace(false), which is the library's own default and therefore a no-op, and no editor template was ever set. Both halves are now wired across every message collector, with the logger and this module excluded from the backtrace. An editor_link preference chooses the scheme; xdebug.file_link_format in php.ini takes precedence when set.
- Gated the Logs page against the full access policy. It renders log file contents but was gated only by admin_header.php, so being a module admin was enough, while Analytics and Diagnostics additionally require debug mode to be on and the module enabled.
- Inferred the core's block-logging contract instead of assuming one, so the status is neither doubled nor untranslatable depending on which core the module runs on.
- Added the direct-access guard to LogCatalog, MonologLogParser and QueryAnalyzer, the only three classes without it.
- Defined 45 _AM_DEBUGBAR_* language constants that the Analytics, Diagnostics, and Ray admin pages referenced but that were never declared. Referencing an undefined constant is a fatal error on PHP 8, so the affected panels crashed rather than rendering.
- Truncated each stored profile column to its own width instead of a single shared 500-character cap. slowest_fp is a normalised SQL fingerprint and routinely exceeds its VARCHAR(255); under MySQL strict mode the oversized insert raised error 1406, which the surrounding catch swallowed, so affected profiles were silently never recorded.
- Recorded the slowest query over every statement rather than only those past the slow-query threshold. On pages where nothing crossed the threshold, slowest_ms was stored as 0.0 and slowest_fp as an empty string, making the Analytics slowest columns and worst-URL ranking wrong.
- Reported the Xdebug environment through the fuller status evaluator (effective modes via xdebug_info() with ini fallback, plus a shared-temporary-directory warning). The Analytics page had been reading keys the previous evaluator never returned, so the panel reported "not loaded" regardless of configuration.
- Indexed request_id on the profiles table. updateVitals() looks a profile up by request id on every web-vitals beacon, once per page view, which without the index scanned the entire retained table. Existing installations gain it through an idempotent migration.
- Realigned sql/mysql.sql with the installer's own CREATE TABLE, which had drifted: the standalone file was missing the lcp_ms, inp_ms, and cls columns that updateVitals() writes to unconditionally.
- Removed an unreachable branch in QueryAnalyzer that tested for a single query shape variant after an earlier guard had already required at least three.
- Revived the on-demand EXPLAIN button, dead since the logger moved real message values into context_json. Four faults hid one another: the button never rendered, because its guard read value.context.is_query while context now carries only null-valued keys; it then hung on "Running..." forever, because it derived the stash key with crypto.subtle.digest(), undefined on a plain-HTTP host, which threw before any promise existed for the .catch() to attach to, so the server now ships the hash it already computed; the returned plan was unreadable, because MySQL 8's tree format is multi-line text and JSON.stringify escaped every newline into one line; and the plan rendered as a narrow strip, because a pre appended straight to a table is invalid and the browser hoisted it into the first column. The shared value resolver also revives the editor source links.
- Followed the surrounding page's dark mode rather than only the operating system's. The toolbar's auto theme asked prefers-color-scheme and nothing else, so a XOOPS theme switched to dark inside a light OS session left a bright white toolbar on a dark page. It now reads data-bs-theme or data-theme from the document first and falls back to the media query, with a MutationObserver so a theme toggle re-themes the bar immediately. An explicit Light or Dark choice still wins.
- Named the open collector when the tab bar is narrow enough that php-debugbar drops every tab label, leaving no indication on screen of which collector was open. The selected tab keeps its label inline while every other tab stays an icon.
- Corrected the per-module "Avg payload KB" column on the Analytics page, which read avg_payload where the query selects avg_payload_kb. The missing key evaluated to (float) null, so the column showed 0.0 for every module; it also divided by 1024 a second time, which the query had already done.
- Carried trigger_value_set on XdebugStatus::read()'s never-throw fallback path, which returned one key fewer than its success path.

<h5>Security</h5>

- Reworked the on-demand EXPLAIN endpoint so the browser never sends SQL. The client now posts a request id and a statement hash, and the server resolves them against a short-lived stash it recorded itself, rejecting anything that is not a SELECT. Generic JSON errors leak neither SQL nor paths.
- Added SqlRedactor, which rewrites every string literal to '' and every numeric literal to 0 before a statement is stashed for EXPLAIN, so a value passed as a literal — a session id, password or token — is not persisted. Note the boundary: SQL comments and identifiers are not literals and pass through unchanged, so a statement that carries data in a comment still carries it after redaction.
- Fixed a literal-scanning flaw that let a secret survive redaction. Single- and double-quoted literals were matched in two sequential passes, so an apostrophe inside a double-quoted value let the single-quote pass stop on the opening quote of a later literal and leave its value intact. Both styles are now matched in one alternation pass.
- The same flaw was present in QueryFingerprinter, where the output is stored as debugbar_profiles.slowest_fp and shown in the Analytics N+1 leaderboard, so an unredacted literal persisted for the whole retention window. Both classes now share one pattern, and an upgrade step clears stored fingerprints that still contain a quote character.
- Extended literal normalisation to quote-free forms. A bare digit rule consumed only the leading 0 of a hexadecimal literal, so 0x534543524554 passed through redaction untouched and reached slowest_fp with its payload intact; binary and exponent forms behaved the same way. All three are now matched explicitly.
- Redaction reports failure instead of returning an empty statement: PCRE's JIT reaches its stack limit on a very long quoted literal and preg_replace() returns null, which a string cast silently turned into ''. Input is length-checked and every pass is checked for failure.
- The scan verifies its own work and refuses when it cannot account for a statement. Backtick identifiers or comments containing a quote character, NO_BACKSLASH_ESCAPES, and unterminated literals could each let a later literal survive; once every literal is removed no quote may remain, and one that does is proof the scan did not model the statement. Those cases now degrade to no EXPLAIN rather than to a leak, and QueryFingerprinter delegates to the same routine.
- Gated beacon.php and explain.php on the shared access policy. The beacon never checked debugbar_enable, so web-vitals rows were accepted with DebugBar switched off; EXPLAIN checked neither debug mode nor the enable switch.

<h5>Changed</h5>

- A test now enumerates which admin pages must sit behind the access policy and which must not, and checks each refusal is escaped and its language constant defined. Nothing pinned that set before, which is why the Logs page omission was invisible.
- The vitals and block-counter migrations share one helper instead of repeating the information_schema existence check. sql/mysql.sql adopts the XMF line's column-per-line layout.
- Replaced the "Profile this request" mechanism. The button previously appended XDEBUG_TRIGGER to the current URL and reloaded, with no server-side gate: the address was replayable by anyone and passed through history, Referer headers and access logs. It now posts to a new xdebug-arm.php, which sets a 60-second one-shot trigger cookie only after checking POST, the shared AccessPolicy decision, a single-use DEBUGBAR_XDEBUG token, and Xdebug's readiness. The cookie is consumed and deleted on the next request whatever the outcome. The xdebug_button_enable preference is unchanged.
- Capped each query-findings list (slow queries, duplicates, N+1 groups, similar shapes) at ten entries. A page issuing thousands of queries previously emitted one entry per finding into the Performance panel, the flight-recorder dump, and the warning log. Reported counts remain exact.
- Sealed the Analytics view model. ProfileRepository, XdebugStatus::read() and AnalyticsBuilder::build() returned untyped arrays, so static analysis could not check any of the admin page's key accesses, and three key-mismatch bugs had already shipped behind that blind spot. Each producer now declares the exact keys it returns, so the page reading a key that is not in the shape is an analysis error rather than a blank cell. The shapes are asserted at the query boundary rather than derived from the SQL, so they catch a mistake in the page but not a renamed alias in the query itself; each shape is kept directly above the query it describes.
- Split the access policy in two. AccessPolicy::isAllowed() still guards the admin pages and requires webmaster-group membership; a new isRuntimeAllowed() guards the toolbar and the three endpoints that serve it, using the same admin flag the preload uses to render the bar. The two had diverged on group membership and on debug_mode 3, so the bar could render buttons whose endpoints answered 403. Both delegate to the same pure predicate.
- Grew the unit suite from four tests to over a hundred, covering the access policy and its two gates, diagnostic sanitiser, SQL redaction and query fingerprinting, Monolog log parsing and cataloguing, system diagnostics, endpoint gating, manifest/preference consistency, and profile-schema consistency. Exact counts are not quoted: they went stale twice while this release was prepared.

<h5>Removed</h5>

- Removed SqlStatementClassifier and ExplainSecretStore. Both existed to make client-submitted EXPLAIN SQL safe, and the redesign above means no client-submitted SQL reaches the endpoint at all.
- Removed the collect_authz preference before release. It offered an Authz tab logging group-permission checks and nothing implemented it, and it could not simply be implemented: checkRight() fires no preload event and xoops_getHandler() caches handlers in a function-local static, so a module cannot decorate the handler. That needs a core-side seam first.

<h5>1.3.3 - [2026-07-28]</h5>
<hr>

<h5>Fixed</h5>

- Pointed the Logs viewer at the XOOPS 2.7.3 core debug log (logs/debug.log under the configured XOOPS data directory). It still pointed at the pre-2.7.3 /log/log.txt, which no longer exists, so the plain-text log was never listed.

<h5>Changed</h5>

- Renamed the plain-text log source from `legacy` to `core`, so the Source column describes the current log rather than a retired one.
- Rendered analytics and log timestamps through formatTimestamp(), so they honour the site's configured timezone rather than the server's. XOOPS applies the site default here rather than each administrator's own offset, so the column reads the same for everyone. The sortable Y-m-d H:i:s layout is kept deliberately, and the trailing timezone abbreviation is dropped because it would name the server's zone rather than the one the value was converted to.
- Held the core log to the same directory containment as the Monolog files when reading. The path is built by the caller and never taken from the request, but the core file logger refuses to write through a symlink, and the reader should not be more trusting than the writer.
